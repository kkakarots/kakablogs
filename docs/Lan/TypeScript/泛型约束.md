

## 泛型约束 `class A<B extends C, D extends E>`？


```typescript
// C 和 E 是已经定义好的基础类型（规则）
interface Animal { name: string }
interface Food { price: number }

// 这里的 class A<B extends C, D extends E> 就是：
class PetShop<TypeForPet extends Animal, TypeForFood extends Food> {
  pet: TypeForPet;
  food: TypeForFood;

  constructor(pet: TypeForPet, food: TypeForFood) {
    this.pet = pet;
    this.food = food;
  }

  printInfo() {
    // 因为有 extends Animal 的约束，TS 确信 pet 一定有 name 属性，绝对不会报错
    console.log(`宠物名字: ${this.pet.name}`); 
  }
}

```

**为什么不直接写死 `pet: Animal` 呢？**
因为写死之后，类型的灵活性就没了。用了泛型，别人在使用时就可以精准传导类型：

```typescript
interface Dog extends Animal { bark(): void } // 狗狗有叫的技能

// 使用时，TS 能精准知道 shop.pet 是 Dog，不仅有 name，还有 bark()
const shop = new PetShop<Dog, Food>(myDog, myFood);
shop.pet.bark(); // 完美类型提示！

```
